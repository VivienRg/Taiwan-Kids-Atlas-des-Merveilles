# Release credentials checklist — Taiwan Kids Atlas

Everything the owner has to obtain before the app can reach a phone. Two items
have real lead times: **Apple Developer Program enrolment** (1–2 days, longer
for an organization needing a D-U-N-S number) and the **Google Play Console
closed-testing requirement** for new personal accounts (12 testers for 14 days
before production is unlocked).

None of these values belong in git. Where each one is stored is in
[secrets.md](secrets.md); the steps that consume them are in
[release.md](release.md) §3, §4 and §6.

## 1. Accounts

| # | Account | Cost | Lead time | Needed for | Where it is used |
|---|---|---|---|---|---|
| A1 | **Apple Developer Program** (Individual or Organization) | US$99/year | 1–2 days (organization: +D-U-N-S) | iOS builds, TestFlight, App Store | EAS credentials + App Store Connect |
| A2 | **App Store Connect** access (same Apple ID, role App Manager) | included | with A1 | creating the app record, TestFlight | dashboard |
| A3 | **Google Play Console** developer account | US$25 once | hours; **new individual accounts: 12 testers × 14 days of closed testing before production** | Android builds, internal testing, production | Play Console + EAS |
| A4 | **Expo account** (free tier is enough to start) | free | minutes | EAS Build / EAS Submit, EAS environment variables | `EXPO_TOKEN` (GitHub secret) |
| A5 | **Supabase** project (Free tier works; **Pro** recommended for daily backups / PITR) | free / US$25 per month | minutes | the production database + Edge Functions + pg_cron | dashboard, GitHub secrets, Vault |
| A6 | **Google Maps Platform** project with the *Maps SDK for Android* API enabled | usage-based (small volume: free tier) | minutes | Android map tiles | `GOOGLE_MAPS_ANDROID_API_KEY` (EAS env) |
| A7 | *(optional)* **Sentry** organisation + project | free tier | minutes | crash reporting ([observability.md](observability.md) §4) | `EXPO_PUBLIC_SENTRY_DSN` |
| A8 | *(optional)* **Slack** incoming-webhook URL | free | minutes | ingestion alerts beyond the GitHub email | GitHub secret |

## 2. Apple signing credentials

EAS manages these; run `eas credentials --platform ios` in `mobile/` and let it
create/store what is missing. What it will hold:

| # | Credential | How to obtain | Notes |
|---|---|---|---|
| I1 | **App ID / bundle identifier** `com.taiwankidsatlas.app` | Apple Developer → Identifiers → App IDs → explicit | Must be **explicit** (no wildcard). **Cannot be changed after the first upload** (architecture.md R7) |
| I2 | **Distribution certificate** (`.p12`) | generated by EAS or exported from Keychain | EAS stores it; a lost certificate can be revoked and recreated |
| I3 | **App Store provisioning profile** | generated by EAS from I1 + I2 | for `production`/store builds |
| I4 | **Ad-hoc provisioning profile + registered devices** | `eas device:create` (owner + each tester opens the link) or the Devices list in the developer portal | only for the `preview-device` profile (real IPA without TestFlight) |
| I5 | **App Store Connect API key** (`.p8` file + **Key ID** + **Issuer ID**) | App Store Connect → Users and Access → Integrations → App Store Connect API → generate a key with the *App Manager* role | Preferred submit credential (no 2FA, no expiring app-specific password). Upload once: `eas credentials` or `EXPO_ASC_API_KEY_PATH` / `ascApiKeyId` / `ascApiKeyIssuerId` |
| I6 | *(alternative to I5)* Apple ID + app-specific password + Team ID | appleid.apple.com → Sign-In and Security → App-Specific Passwords | Only if API keys are not an option; EAS asks for them interactively |
| I7 | **App Store Connect app record** (name, SKU, primary language, category) | App Store Connect → My Apps → New App | `eas submit` needs the record to exist; note its numeric **Apple ID** for `submit.ios.ascAppId` if you set it in `eas.json` |

## 3. Google signing credentials

| # | Credential | How to obtain | Notes |
|---|---|---|---|
| G1 | **Upload keystore** (`.jks`/`.keystore` + password + alias) | generated and stored by EAS (`eas credentials --platform android`) | **Back it up.** Without the upload key you cannot update the app unless Play App Signing allows a key reset |
| G2 | **Play App Signing** | enabled automatically on the first AAB upload | Google holds the *app signing key*; the SHA-1 you restrict the Maps key with is the **app signing certificate SHA-1** from Play Console → Setup → App integrity |
| G3 | **Play service-account JSON** | Play Console → Setup → API access → link a Google Cloud project → create a service account with *Release to testing tracks* (and *Manage production releases* later) → download the JSON | Upload once to EAS (`eas credentials`) — do **not** commit it. `eas.json` targets the `internal` track |
| G4 | **Google Maps Android SDK key** | Google Cloud Console → APIs & Services → Credentials → API key | Restrict it to *Android apps* with package `com.taiwankidsatlas.app` + the SHA-1 of G2 (and of your local debug/upload key for dev builds). Stored as `GOOGLE_MAPS_ANDROID_API_KEY` in EAS environment variables per profile |
| G5 | **Play Console app record** (name, package, category, content rating questionnaire, data-safety form, privacy policy URL) | Play Console → Create app | Required before the first upload completes |

## 4. Checklist

```
Accounts
[ ] A1 Apple Developer Program active (Team ID noted)
[ ] A2 App Manager access to App Store Connect
[ ] A3 Google Play Console account (note the testing requirement for new accounts)
[ ] A4 Expo account + `EXPO_TOKEN` created and stored as a GitHub secret
[ ] A5 Supabase project created in the chosen region; DB password in a password manager
[ ] A6 Maps SDK for Android enabled in Google Cloud
[ ] A7 (optional) Sentry project + DSN
[ ] A8 (optional) Slack webhook for alerts

Apple
[ ] I1 explicit App ID com.taiwankidsatlas.app registered
[ ] I2 I3 distribution certificate + App Store profile stored on EAS
[ ] I5 App Store Connect API key (.p8, Key ID, Issuer ID) uploaded to EAS
[ ] I7 app record created in App Store Connect (note its numeric Apple ID)
[ ] I4 (optional) devices registered for the preview-device profile

Google
[ ] G1 upload keystore generated + backed up (two copies, offline)
[ ] G2 Play App Signing enabled; app signing SHA-1 recorded
[ ] G3 service-account JSON uploaded to EAS with release permissions
[ ] G4 Maps key restricted to package + SHA-1, set as an EAS environment variable
[ ] G5 Play listing metadata, content rating and data-safety form completed

Store-facing app facts (verify once, then freeze)
[ ] app name      : Taiwan Kids Atlas
[ ] bundle/package: com.taiwankidsatlas.app
[ ] version       : from mobile/app.json (1.0.0) — production builds auto-increment
[ ] privacy policy URL published; the app stores location only in query params and
    favourites only on the device (architecture.md §7)
[ ] licence attribution visible in Settings → About (api-contract.md §7, 顯名聲明)
```
